# AutoReg Assistant — технический аудит v1 / v2 / v3 и отчёт о сборке v3.1.0

Дата: 2026-09-03. Метод: чтение всех исходников трёх архивов + запуск каждого
расширения в headless Chrome 152 (`--load-extension`) на локальных фикстурах
(обычная форма, форма с подсказкой «disposable not allowed», двухшаговая
регистрация, «Confirm email», страница логина, страница со строгим CSP) с
живыми запросами к tempmail.lol / mail.tm / GuerrillaMail. Юнит-прогон
парсера писем в Node 24.

## 2. Критические дефекты (воспроизведены)

### v1 и v3: `Failed to fetch dynamically imported module`
`content/content.js` — классический скрипт, который делает
`import(chrome.runtime.getURL("core/form-filler.js"))`. В MV3 ресурс
расширения доступен странице только из `web_accessible_resources`. Ключа нет
→ все 5 (v1) / 6 (v3) модулей не загружаются, `await modules.*` виснут в
rejected-промисах: нет инлайн-кнопки, `INSPECT_FIELDS` не отвечает, OTP не
вставляется, баннеров нет. Внешне расширение «установлено», popup даже
генерирует email. README v3 при этом заявляет «исправлены все баги обеих
версий» — сборка не запускалась в браузере.

Проверено дополнительно: `use_dynamic_url: true` для этого паттерна **не
подходит** — модуль `inline-button.js` импортирует `../core/form-filler.js`
относительным путём, который резолвится в статический ID расширения, и Chrome
отвечает `Denying load of chrome-extension://<static-id>/core/form-filler.js`.
Поэтому в v3.1 — статические URL и точный список файлов вместо `*.js`.

### v2: ложные `ERROR_SUBMITTED`
`scanForError()` прогоняет классификатор по всему `document.body.innerText`
по любой мутации DOM сразу после заполнения, без ожидания сабмита. На
фикстуре со статичной подсказкой «disposable email addresses are not allowed»
без единого сабмита: 3 ретрая, 3 ящика, домены `emalupe.com`,
`guerrillamailblock.com`, `xc.firegameplay.com` навсегда в блэклисте сайта.
В v1/v3 ошибки ищутся только в видимых `[role=alert]`/`.error`-контейнерах и
только после сабмита — этот подход и сохранён.

### v3: многошаговые формы не запускаются
`hasRegistrationForm()` требует email **и** пароль. На шаге 1 («введите
email → Continue») кнопка возвращает `form_not_found`, сессия наблюдения не
стартует, шаг 2 не заполняется. Кроме того, сессия слушала только
`childList`, а сайты часто показывают шаг 2 снятием `hidden`/`display:none`.

### v1/v3: ссылки из HTML-писем
mail.tm и GuerrillaMail делают `stripTags(html)` до парсинга, tempmail.lol
`html` не пробрасывает. Письмо вида `<a href="…/verify?token=…">Confirm</a>`
→ `link: null` (юнит-тест). Обратная сторона: приветственное письмо
GuerrillaMail содержит `http://www.guerrillamail.com/` — v1/v3 считали его
«ссылкой подтверждения» и в режиме `linkMode=auto` открыли бы её как
верификацию.

## 3. Дефекты логики (по коду, частично воспроизведены)

- **OTP ⇒ verified.** v3 ставит `verified` сразу после вставки кода в поле,
  до ответа сайта. Неверный/просроченный код → «успех». v3.1: статус ставится
  по `PAGE_VERIFIED` от страницы либо через 8 с без `ERROR_SUBMITTED`.
- **Гонка записи `ar_records`.** Поллинг (каждые 5 с), контент (`SUBMITTED`,
  `ERROR_SUBMITTED`) и popup делают read-modify-write одного массива без
  сериализации: `attempts` от тика затирает `status` от `SUBMITTED` и
  наоборот. v3.1: очередь промисов вокруг всех мутаций.
- **Ротация провайдеров не работала** в v1/v3: счётчик в памяти SW, а SW MV3
  засыпает через ~30 с — каждый вызов начинался с 0 → всегда первый провайдер
  (в E2E v3.1 `ar_rotationIndex` растёт 1→2→3 между вызовами).
- **Поллинг после сна SW** ждал будильника (30 с) и при возобновлении
  сбрасывал дедлайн. v3.1: `resumePolls()` на холодном старте, дедлайн
  сохраняется, первый тик немедленно.
- **Повторный SUBMITTED** (шаг 2) откатывал `pending_verification` →
  `submitted`.
- **Сессия шагов переживала ретрай**: после `ERROR_SUBMITTED` и перегенерации
  email старая сессия дозаполняла форму прежним адресом.
- **v2 mail.tm**: токен — голый JWT без учёток; протух → поллинг молча умирает.
  В v1/v3 токен = JWT+логин+пароль с перелогином по 401 (оставлено).
- **v2 `CONFIRM_RE` содержит голую `2`** → класс `mb-2`/`col-12` делает поле
  паролем-подтверждением. В v3 регэксп v1 (`(pass|pwd)[-_]?2\b` только по
  name/id).

## 4. UI / протокол

- v3 popup: `p.name` vs `meta.title` → `undefined` в селекте провайдеров;
  контекстное подменю строилось из несуществующего `meta.name`.
- v1 popup: `.view{display:flex}` перебивает `[hidden]` — три экрана
  одновременно (в v3 исправлено).
- Инлайн-кнопка ставилась на каждое email-поле, включая «Confirm email».
- Права: v2 просит `<all_urls>` + `clipboardWrite`; v3 — `clipboardWrite`
  без использования; v3 `host_permissions: https://*/*` при
  `content_scripts.matches: <all_urls>` → на http-сайтах скрипт не
  внедрялся. v3.1: `http/https` симметрично, `clipboardWrite` убран.

## 5. Безопасность

- UI строится через `createElement`/`textContent`; `innerHTML` — только для
  собственных SVG-констант (v2/v3). Тела писем в popup не рендерятся как HTML.
  `html` из провайдеров идёт только в парсер (регэкспы), не в DOM.
- Пароли: AES-GCM-256, PBKDF2-SHA256 200k, соль 16 байт, IV 12 байт,
  верификатор. Мастер-пароль в `chrome.storage.session` (не на диске; живёт
  до перезапуска браузера). Приемлемо для локального журнала; слабое место —
  минимальная длина мастер-пароля 4 символа (рекомендую ≥ 8).
- `emailToken` mail.tm содержит пароль почтового аккаунта в base64 в
  `storage.local` в открытом виде; шифруется только `password` записи.
  Рекомендация: шифровать `emailToken` тем же ключом (см. §7).
- Кастомные провайдеры: только `https://`, `getPath` — только чтение, но
  ходил по прототипу (`"constructor.name"` возвращал `"Object"`); в v3.1
  ограничен собственными ключами (`hasOwnProperty`).
- Host permissions широкие (`http/https://*/*`) — это цена инлайн-кнопки на
  любом сайте; альтернатива с `activeTab` потребует клика по иконке.

## 7. Предложения по улучшению (не вошли в 3.1, по приоритету)

1. **Автотесты.** Ни в одной версии нет тестов, хотя модули `core/*` чистые.
   Минимум: Node-тесты для `email-parser`, `password-generator`,
   `error-classifier`, `custom-parser.validateConfig`; E2E-харнесс из этого
   аудита (`run-e2e.py`) — в CI на фикстурах без сети (mock провайдеров через
   `chrome.declarativeNetRequest`/локальный сервер).
2. **Шифровать `emailToken`** тем же ключом, что и `password` — сейчас в нём
   пароль mail.tm в открытом виде.
3. **Единый `poll loop`** вместо `setInterval` на запись (как в v2): один
   `setTimeout`, обход всех job'ов, меньше параллельных `fetch` и проще
   уважать лимит mail.tm 8 QPS (сейчас `getMessages` mail.tm делает до 11
   запросов за тик).
4. **Провайдер по домену сайта.** Хранить статистику успеха
   `{siteDomain: {provider: {ok, fail}}}` и выбирать по ней; блэклист
   доменов дополнять «серым» списком с TTL (домены temp-mail часто
   ротируются, вечный блэклист устаревает).
5. **Детект полей через `autocomplete`** как приоритетный сигнал
   (`new-password`/`current-password`/`one-time-code`/`username`): даёт вид
   формы (login vs signup) и OTP-поле надёжнее регэкспов по `name`.
6. **Shadow DOM сайтов.** `document.querySelectorAll("input")` не видит поля
   внутри теневых деревьев (web-компоненты, часть SPA). Нужен обход
   `shadowRoot` (открытых).
7. **`fillMode: full` по умолчанию** либо подстановка username, когда поле
   `required` — сейчас формы с обязательным username не проходят сабмит.
8. **i18n.** Все строки на русском в коде; вынести в `_locales/` — это ещё и
   требование магазина при публикации.
9. **Права.** Рассмотреть `optional_host_permissions` + `activeTab`: кнопка
   появляется после первого клика по иконке на сайте, зато без «читает данные
   на всех сайтах» при установке.
10. **Кастомные провайдеры**: поддержать `{{email}}` в `getMessages.url`
    (README обещает, парсер v1/v3 не подставляет), `expiresAt`/`expired` в
    маппинге, тестовую кнопку с показом сырого ответа для отладки маппинга.
11. **Отказоустойчивость поллинга**: при `expired: true` от tempmail.lol
    (ящик живёт ~1 ч) завершать запись с понятным статусом, а не ждать таймаут.
12. **Уведомления**: кнопки действий в `chrome.notifications` («Открыть
    ссылку», «Скопировать код») вместо клика по всему уведомлению.
