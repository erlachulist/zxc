# AutoReg Assistant

Расширение Chrome (Manifest V3) для быстрой регистрации на сайтах через **временную почту**. Один клик — плавающая кнопка-«молния» рядом с полем email, кнопка в попапе, контекстное меню или горячая клавиша — выполняет весь цикл: создаёт временный ящик, заполняет email / пароль / подтверждение / имя, сохраняет запись в журнал, ждёт письмо и **автоматически подтверждает регистрацию** по коду (OTP) или ссылке.

**v3.1** — исправленная сборка v3: та же архитектура (ES-модули v1 + интерфейс и возможности v2), но расширение реально запускается на страницах (в v3 отсутствовал `web_accessible_resources`, и ни один content-модуль не загружался), работают многошаговые формы, ссылки из HTML-писем и ротация провайдеров. Список изменений — в конце файла.

Все данные хранятся **локально** (`chrome.storage.local`). Ничего не отправляется на сторонние серверы, кроме API самих сервисов временной почты.

---

## Установка (Load unpacked)

1. Откройте `chrome://extensions`.
2. Включите **Режим разработчика** (переключатель справа сверху).
3. Нажмите **Загрузить распакованное расширение** и выберите папку `autoreg-assistant/` (в которой лежит `manifest.json`).
4. Значок AutoReg появится на панели. Закрепите его для удобства.

Работает в Chrome, Edge, Brave и других браузерах на Chromium. Открытые до установки вкладки нужно обновить (F5).

## Как пользоваться

### Способ 1 — инлайн-кнопка (рекомендуется)
Откройте страницу регистрации. Рядом с полем email появится кнопка-молния. Нажмите её — ассистент создаст email, заполнит форму и начнёт следить за подтверждением. После отправки формы он сам проверит почту, вставит код (и нажмёт кнопку подтверждения) или откроет ссылку.

### Способ 2 — попап
Клик по значку расширения → **Заполнить форму** (текущая вкладка) или **Email** (только адрес). В панели сразу видны **текущий email, пароль и письма** (кнопка «Проверить почту»), ниже — журнал всех регистраций с кнопкой **⚡ заполнить форму данными этой записи** у каждой. Выбор провайдера — выпадающий список «Провайдер».

### Способ 3 — контекстное меню / горячая клавиша
Правый клик на странице → **AutoReg: заполнить форму** / **только email** / **Сгенерировать email через…** (выбор провайдера).
Горячая клавиша: **Ctrl+Shift+F** (macOS: **⌘+Shift+F**).

### Вход на знакомый сайт (v3)
Когда вы возвращаетесь на сайт, где уже регистрировались, и видите **форму логина**, ассистент не создаёт новую регистрацию: он показывает баннер **«Войти как {email}»** и по кнопке «Заполнить форму» подставляет сохранённые email и пароль. То же самое делает кнопка **⚡** у любой записи в журнале.

### Многошаговые формы (v3)
Если регистрация разбита на шаги (шаг 1 — email, шаг 2 — пароль), ассистент после первого шага продолжает следить за страницей: новые поля пароля заполняются теми же данными автоматически, а при более строгих требованиях шага пароль перегенерируется под них.

## Возможности

- **Один клик** — полный цикл: email → пароль → отправка → верификация → вход.
- **Умный генератор пароля** — читает требования поля (`minlength`, `maxlength`, `pattern`) **и текст рядом с формой** («at least 8 characters, uppercase, special»), генерирует пароль с гарантированными классами символов и циклом проверки по pattern (v3: исправлены баги pattern-генерации обеих версий).
- **Многошаговые формы** — автозаполнение новых полей следующих шагов (v3).
- **Автоверификация**: опрос почты, извлечение OTP-кода с учётом контекста, автозаполнение обычных и сегментированных полей (по цифре), **авто-нажатие кнопки подтверждения** после вставки кода (v3), ожидание появления поля кода, если оно ещё не отрисовано (v3, pending-режим), баннер с кодом и кнопкой «Копировать» как последний резерв. Ссылки — фоновая вкладка (auto) или баннер (manual).
- **Журнал регистраций** — сайт, email, пароль, имя, статус, история попыток, теги, заметки; поиск, детали, экспорт; кнопка **⚡ «заполнить форму»** у каждой записи (v3).
- **Вход сохранёнными данными** — детект формы логина + баннер-предложение (v3).
- **Повторы и failover** — при ошибке сайта («email занят», «одноразовая почта запрещена») ассистент берёт новый адрес (экспоненциальный backoff) и заносит отклонённый домен в чёрный список для сайта. Русскоязычные тексты ошибок классифицируются корректно (v3: исправлен баг `\w` без кириллицы из v2).
- **Несколько провайдеров** с ротацией: `tempmail.lol`, `mail.tm`, `guerrillamail`. Стратегии: по кругу / случайно / успешный для сайта.
- **Свои провайдеры** — декларативный JSON без кода, с `{{apiKey}}`.
- **Опциональное шифрование** паролей мастер-паролем (PBKDF2 200k + AES-GCM; ключ только в памяти).
- **Экспорт** JSON и CSV для KeePass; статистика по сайтам и провайдерам.
- **Тёмная тема** интерфейса (popup + настройки).

## Настройки (страница опций)

**Заполнение** — режим (email / +пароль / всё), автоотправка, многошаговые формы, авто-подтверждение кода.
**Верификация** — интервал и таймаут опроса почты, режим ссылок (auto/manual), уведомления, предложение входа.
**Надёжность** — стратегия провайдера, число повторов, базовая задержка, автоудаление (подтверждённые записи с паролями не удаляются никогда — v3).
**Провайдеры** — включение/выключение, добавление своих (JSON + живой тест).
**Безопасность** — включить/выключить шифрование, блокировка/разблокировка.
**Данные** — экспорт JSON, CSV для KeePass, очистка журнала.
**Статистика** — сводка по статусам, сайтам и провайдерам.

## Свой провайдер (JSON)

На вкладке **Провайдеры** → «Добавить свой провайдер». Плейсхолдеры: `{{token}}`, `{{apiKey}}`, `{{email}}`. Пути в ответе — через точку (`data.messages.0.id`).

```json
{
  "name": "my-tempmail",
  "apiKey": "секрет-для-Authorization",
  "domains": ["example-mail.com"],
  "createInbox": {
    "url": "https://api.example-mail.com/inbox",
    "method": "POST",
    "headers": { "Authorization": "Bearer {{apiKey}}" },
    "body": {},
    "responseMapping": { "email": "data.address", "token": "data.token" }
  },
  "getMessages": {
    "url": "https://api.example-mail.com/inbox/{{token}}/messages",
    "method": "GET",
    "responseMapping": {
      "messages": "data.messages",
      "from": "from", "subject": "subject",
      "body": "text", "receivedAt": "createdAt"
    }
  }
}
```

Обязательны: `name`, `createInbox.url`, `createInbox.responseMapping.email`, `getMessages.url`, `getMessages.responseMapping.messages`. Кнопка «Добавить» сначала делает **живой тест** (создаёт ящик и читает письма).

## Архитектура

```
manifest.json            — MV3-манифест (SW-модуль, content, popup, options, хоткей)
background/service-worker.js — сеть, хранилище, поллинг, ретраи, шифрование, логин-флоу
core/                    — генератор пароля, форм-филлер (+вид формы), crypto, парсер писем,
                           классификатор ошибок, ретраи
providers/               — интерфейс, 3 встроенных провайдера, реестр (ротация/failover), JSON
storage/                 — схема данных и обёртка chrome.storage.local (ключи ar_*)
content/                 — оркестратор (многошаговые формы, логин-детект, OTP-pending),
                           инлайн-кнопка, баннер, OTP-автозаполнение
popup/, options/, ui/    — интерфейсы (общая тема ui/theme.css)
```

Код без сборки: service worker и контентные модули — **ES-модули** (официальный паттерн MV3, динамический import в изолированном мире); все сетевые запросы идут из service worker; UI на странице — только через Shadow DOM; вкладки открываются только через `chrome.tabs.create`.

## Ограничения

- **CAPTCHA / антибот** — расширение не обходит проверки «я не робот». На таких формах завершите шаг вручную.
- **Блокировки одноразовой почты** — часть сайтов отклоняет домены temp-mail. Ассистент попробует другого провайдера, но 100% гарантии нет.
- **Автоотправка** выключена по умолчанию — включайте осознанно (авто-подтверждение кода включено по умолчанию и работает только после того, как код найден в письме).
- Сервисы временной почты публичны: **не используйте** ассистент для важных/платёжных аккаунтов.
- Инлайн-кнопка и баннеры появляются на обычных страницах (http/https), но не на служебных (`chrome://`, страница магазина).

Используйте ответственно и в рамках правил сайтов.

## Что исправлено в 3.1.0 (относительно 3.0.0)

Критические
- **Расширение не работало на страницах.** `content.js` грузит модули через `import(chrome.runtime.getURL(...))`, а в манифесте не было `web_accessible_resources` → все модули падали с `Failed to fetch dynamically imported module`: ни кнопки, ни заполнения, ни OTP. Добавлен точный список из 6 модулей (не `*.js`, чтобы не светить сайтам лишние файлы), `matches` — http/https.
- **Многошаговые формы не запускались.** Шаг 1 «только email» отбраковывался как «нет формы регистрации». Добавлен детект `isEmailFirstStep` (email + кнопка Continue/Sign up, без пароля; логин по email и восстановление пароля исключены), сессия шагов видит появление шага 2 через атрибуты (`hidden`/`style`/`class`), после дозаполнения переводит наблюдение за сабмитом на новую форму и продлевает дедлайн поллинга (`STEP_FILLED`).
- **Терялись ссылки подтверждения из HTML-писем.** Провайдеры срезали разметку до парсинга, tempmail.lol не отдавал `html` вовсе. Теперь провайдеры пробрасывают `html`, парсер берёт URL из `href="…"`, декодирует `&amp;`, а ссылкой верификации считает только URL с признаками verify/confirm/activate/token — URL сайта из футера письма больше не «подтверждает» регистрацию.
- **Приветственное письмо GuerrillaMail** отфильтровано — оно содержало ссылки и могло открываться как «подтверждение».

Логика
- Статус `verified` не ставится по факту вставки OTP: ждём `PAGE_VERIFIED` от страницы или 8 с без ошибки (иначе неверный/просроченный код помечался успехом).
- Повторный `SUBMITTED` (шаг 2) не откатывает `pending_verification` → `submitted`.
- Поллинг возобновляется при холодном старте service worker сразу, а не только по будильнику через 30 с; при возобновлении сохраняется исходный дедлайн; первый тик — немедленно.
- Ротация провайдеров хранится в `storage.local` (счётчик в памяти SW сбрасывался при каждом засыпании — «ротация» всегда выбирала первого провайдера).
- Запись в `ar_records` сериализована очередью — параллельные тики поллинга, сообщения контента и popup больше не затирают изменения друг друга.
- Сессия шагов закрывается при `ERROR_SUBMITTED`/`PAGE_VERIFIED` и не запускается в режиме «только email» — убрано дозаполнение старым email после ретрая.

UI / мелкое
- Popup показывал `undefined` вместо имён провайдеров; контекстное подменю «Сгенерировать через…» получало несуществующий `meta.name`.
- Инлайн-кнопка — одна на форму (у поля «Confirm email» дублирующей кнопки нет; клик заполняет оба поля).
- Кастомный провайдер: отдельный маппинг `html` (раньше `html` был запасным путём для `body`).
- Права: убран неиспользуемый `clipboardWrite`, добавлен `http://*/*` (сайты без TLS не получали content-скрипт), `minimum_chrome_version: 120` (chrome.alarms с периодом 30 с).
